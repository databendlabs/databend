# Loki object-store chunk fixtures

These files are generated by the official **grafana/loki v3.4.2** encoder, using
`pkg/chunkenc.MemChunk` and `pkg/storage/chunk.Chunk.Encoded`. They are binary
object-store envelopes, not Push API JSON. Names deliberately have no extension.

Regenerate with Go 1.23 or later:

```sh
cd tests/data/loki/generate
go mod tidy
go run .
```

`chunks/` contains V1/gzip and V2–V4 with all nine supported codecs (28 files).
Each contains three nanosecond-separated logs, stream labels `env=test` and
`service=api`, tenant `test-tenant`, and multiple blocks. V4 also contains per-log
`trace_id` structured metadata. `empty` has no logs. `bad-crc` is generated by
flipping one byte of the block metadata checksum in a valid V3 envelope.

## Import contract

```sql
CREATE TABLE logs (
    timestamp_ns BIGINT,
    labels VARIANT,
    message STRING,
    tenant_id STRING,
    structured_metadata VARIANT
) ENGINE = FUSE;

COPY INTO logs FROM @stage/chunks/ FILE_FORMAT = (TYPE = LOKI);
```

Direct COPY matches these fields by name using the target schema. Dynamic labels
are not flattened and message strings are not automatically parsed as JSON.
`MISSING_FIELD_AS` defaults to `ERROR`; `NULL` and `FIELD_DEFAULT` work as with
other structured input formats. `COLUMN_MATCH_MODE` supports `CASE_INSENSITIVE`
(the default) and `CASE_SENSITIVE`; positional matching is rejected. Legacy chunks
return `{}` for structured metadata.

SELECT exposes each log as `$1` VARIANT, so a different target schema can be mapped
without creating a named format:

```sql
COPY INTO app_logs (event_ns, service, content)
FROM (
    SELECT $1:timestamp_ns::BIGINT, $1:labels:service::STRING, $1:message::STRING
    FROM @stage/chunks/
)
FILE_FORMAT = (TYPE = LOKI);
```

`CREATE FILE FORMAT ... TYPE = LOKI` is optional and uses the same reader.
Keep nanosecond timestamps as `BIGINT` when full precision matters; Databend
`TIMESTAMP` has microsecond precision.

Only object-store chunk envelopes with outer encoding 128/129 and inner versions
V1–V4 are supported. Indexes, WAL/checkpoints, raw inner chunks, Push API JSON,
export, streaming load, and schema evolution are not supported. Use stage paths,
`FILES`, or `PATTERN` to select chunks in buckets that also contain indexes.
Compression is read from the chunk, so an explicit `COMPRESSION` option is rejected.

All inner section CRC32C checksums are checked. The outer object checksum normally
lives in its object key, not the file contents; it is not checked because arbitrary
renamed/copied stage files must remain readable. Structurally invalid chunks abort
regardless of `ON_ERROR`; `ON_ERROR=CONTINUE` skips only target-field conversion
errors. The reader never publishes partially decoded corrupt files.

The current pipeline reads a whole compressed file and buffers its output until
validation succeeds. The reader imposes no additional fixed size limits on decoded
blocks, symbol tables, or outer metadata beyond the native format's length fields.
Files are decoded independently and output columns are flushed at COPY block
thresholds. Memory consumption depends on the compressed file and its decoded
contents. Real production files still need compatibility validation before rollout,
particularly when running a Loki version other than v3.4.2.
