## Summary

Record only, not for merge. This PR keeps a local ClickBench comparison between the Databend version ClickBench currently runs (v0.9.53) and current builds, done to decide whether bumping the version in ClickBench is worth it. It adds `benchmark/clickbench-versions/`: scripts, environment manifest, raw results and the report. No code changes.

What was compared, all with the default configuration (ClickBench's `config.toml`):

- Official packages v0.9.53-nightly, v1.2.955-nightly (before encoded columns #20819) and v1.2.967-nightly.
- `official-967`: v1.2.967's commit `25ca45599d`, built locally with the x86_64 release CI parameters (thin LTO, codegen-units 1, opt-level `s`, `+sse4.2`, debug info stripped).
- `official-main-prs`: upstream/main `177b395dd3` plus #21138 and #21144, built the same way.

Method: ClickBench's `create.sql` (with `CLUSTER BY`) and `queries.sql`. For each query and release: stop meta and query, evict all release files from the page cache, restart, then run the query 3 times (cold, then hot = min of runs 2 and 3). Runs are pinned to 16 logical CPUs. Releases are interleaved per query over 2 rounds, with the order reversed in round 2. The container cannot write `drop_caches`, so cold runs use `posix_fadvise(DONTNEED)` instead.

|---|---:|---:|---:|---:|
| v0.9.53 | 38.66 s | 30.36 s | 13.1 GiB | 1.000 |
| v1.2.955 | 40.61 s | 32.36 s | 15.0 GiB | 1.582 |

Findings:

- **The local build reproduces the official package.** `official-967` vs v1.2.967: hot geomean 1.029, and no query differs consistently.
- **main + #21138 + #21144 vs `official-967`.** Hot sum is 4.8% lower, cold sum 2.5% lower, and per-query peak RSS geomean 17% lower. 9 queries are consistently faster (Q20 −27%, Q10/Q11 −14%) and none are slower.
- **Against v0.9.53.** Hot sum is 26% lower, but 22 queries are consistently slower.
- **Most of those 22 regressions come from the storage format, not from code.** v0.9.53 writes Native by default (`SyncReadNativeDataSource`). 1.x only writes Parquet: creating a Native table fails with `native storage_format is no longer supported`. `probes/run_probes.py format` gives v0.9.53 a Parquet copy of `hits`. With both sides on Parquet, 11 of the 17 queries tested are faster on main + PRs, for example Q20 0.71×, Q22 0.77×, Q27 0.72×, Q10 0.73× and Q24 0.15×. Q03 goes from 2.3× slower to 1.04×.
- **Still slower on the same format:** Q01 (+9 ms), Q02 (+18 ms) and Q07 (+14 ms), all small queries. The cause is not found yet. Turning on the block meta caches does not change them.
- **`length` changed meaning.** It counts bytes in v0.9.53 and characters in 1.x, so Q27/Q28 return different averages. With `octet_length`, Q27 gives v0.9.53's result and runs in 0.93 s instead of 1.06 s.
